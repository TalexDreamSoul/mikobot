# Convergence design

## Boundaries and decisions
- Preserve host CLI/token WebUI behavior; proxy:/oidc: principals remain external. InboundMessage.source is explicit producer-owned provenance (external/runtime), never inferred from a sender label, input metadata or thread override. Persist and replay that source for pending work, then revalidate stored user/project identity.
- WebUI public websocket:<chat> IDs remain stable; ownership metadata pins their user/project and is checked on every attach/read/message. Reject mixed or missing scoped state rather than upgrading it. Non-WebUI collaboration keys become user:<uid>:project:<pid>:<original key> (unified:<uid>:project:<pid> for explicit member unification). Existing unscoped member history stays untouched; do not adopt it into another project.
- ConversationScope remains the internal capability contract. Add COLLABORATION_ASSIGNMENT_METADATA_KEY = collaboration_assignment_required (boolean provenance); resolve_session_scope adds keyword assignment_required: bool = False and binding_id: str | None = None. Record true whenever the source scope has an assignment or channel requires one. Repository validates membership, assignment existence/enabled/project and exact binding when supplied; default WebSocket/personal unassigned channels retain valid member routing.
- Member profiles and automatic archives live outside shared files at users/<uid>/projects/<pid>. Host memory follows the configured agent workspace even when the host selects another working directory. Member prompts, private Dream tools and consolidation use the exact private owner, while project AGENTS/explicit Skills use the shared workspace. Unbound scopes have no host profile, Skill/MCP grants or host-memory ingestion. Do not migrate ambiguous history. Legacy namespace migration recognizes only the old exact shape and preserves new project-qualified keys across restarts.
- Tools receive the trusted ConversationScope and a typed authorize_tool callback; queued subagents preserve both. Revalidate immediately before actual invocation. Consolidation validates before remote archive work and excludes host instructions/tool schemas. Private Dream tool construction intersects—not replaces—current private file capabilities; its relative paths stay private and raw journals/shared project writes remain prohibited.
- Member arbitrary code requires supported bwrap per-exec sandbox on Linux; deny unsandboxed/unsupported execution, including CLI app bypasses. bwrap must isolate PID/IPC/network and not mount global media/config or propagate credentials. Host shell compatibility remains except explicit configured sandbox never silently falls back. No claims of native bwrap validation on macOS.
- Extensions remain projections of existing owners. Installed/enabled markers are desired state, not proof of MCP health. Use existing lifecycle/diagnostic contracts for failed or unavailable runtime and existing actions for retry; no persistent duplicate runtime DB.
- Frontend authorization improves UX only; backend remains authoritative. Existing collaboration.isAdmin is the frontend role source. Member settings limited to local appearance and accessible project/channel surfaces; no global host inventory requests from hidden views. Apps = capability management; Extensions = runtime inventory. Remove unsupported --include-nanobot/--project-id export options.

## Ownership
CorePrivacy owns loop/context/memory/autocompact/subagents, session/privacy and any required session namespace consumers; StoreAuthorization owns collaboration models/store/repository/local_repository; SandboxPrivacy owns shell/sandbox/CLI execution/filesystem/path/media policy; ProductSurfaces owns webui source (not tests); ExtensionLifecycle owns extensions and cli MCP export. Main owns webui/ws_http.py and inbound gateway access integration, safe runtime execution, docs and final integration. Three Tester slices own regression files only. Shared-file edits require explicit coordination; Main is integration owner.

## Verification and migration
No real runtime configuration is read during smoke runs; each run sets temporary HOME/config/workspace and synthetic credentials. Preserve old files and refuse ambiguous authority. Full backend testpaths include channel packages and run with isolated homes; frontend tests/lint/build cover host/member role loading. Actual browser smoke uses a real gateway, local model spy, and two local authenticated HTTP/WebSocket proxies. Native Bubblewrap file/process/network/env isolation was exercised in an ephemeral Linux container mounting only the implementation module read-only; SYS_ADMIN and NET_ADMIN enable that fixture's nested namespaces. Native macOS additionally verifies fail-closed execution and handles unsupported SO_ACCEPTCONN using live asyncio server/descriptor state.
